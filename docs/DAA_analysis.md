# DAA Analysis — Algorithm 2035

## 1. Abstraction (scenario → model)

| Scenario | Model | Objective | Size parameters |
|---|---|---|---|
| Connect hospitals / gateways | undirected weighted graph G(V,E) | min total edge weight, graph connected | V, E |
| Costs between all zones | directed weighted graph, matrix | all-pairs shortest cost | V |
| Fund projects within budget | items (cost wᵢ, benefit vᵢ), capacity W | max Σ benefit s.t. Σ cost ≤ W | n, W |
| Sensor records index | ordered keys, lookup mix | few node/page accesses | n, storage medium |
| Maintenance events | priority queue with decrease-key and merge | min total heap work | n, decrease-keys/event |
| Interfering sensors | n×n grid, row/column/diagonal conflicts | any conflict-free placement | n |
| Inspection tour | complete weighted graph | min-cost Hamiltonian cycle (TSP) | n |
| Route feasibility | undirected graph | does a Hamiltonian cycle/path exist | V, E |
| Processing pipeline | dimension sequence p₀…pₙ | min scalar multiplications | n |

## 2. Time and space

| Technique | Time | Space | Why correct |
|---|---|---|---|
| Prim, binary heap | O((V+E) log V) | O(V+E) | cut property |
| Prim, adjacency matrix | O(V²) | O(V²) | cut property; scan replaces heap |
| Kruskal | O(E log E) | O(V+E) | cycle property + union-find |
| Floyd–Warshall | O(V³) | O(V²) | after phase k, d[i][j] uses only intermediates ≤ k |
| Fractional Knapsack | O(n log n) | O(n) | exchange argument |
| 0/1 Knapsack DP | O(nW) | O(nW) | best(i,c)=max(best(i−1,c), vᵢ+best(i−1,c−wᵢ)) |
| Red-Black Tree | O(log n) search/insert, ≤ 2 rotations/insert | O(n) | height ≤ 2log₂(n+1) |
| B-Tree (min degree t) | O(t·log_t n) CPU; O(log_t n) node accesses | O(n) | equal-depth leaves; t−1..2t−1 keys |
| Binomial Heap | O(log n) insert/merge/extract/decrease-key (worst) | O(n) | ≤ log₂n+1 trees |
| Fibonacci Heap | O(1) amortized insert/merge/decrease-key; O(log n) amortized extract-min | O(n) | potential method |
| N-Queen backtracking | exponential worst case | O(n) | exhaustive DFS, prune only on conflict |
| Hamiltonian backtracking | O(n!) | O(n) | exhaustive DFS over simple paths |
| TSP backtracking | O((n−1)!) | O(n) | enumerates all tours |
| TSP branch & bound | O((n−1)!) worst case | O(n) | prunes only if lower bound ≥ best tour |
| Matrix Chain DP | O(n³) | O(n²) | optimal substructure on split point |

**Branch & bound lower bound.** For a partial tour ending at city u with cost c: `c + minOut(u) + Σ_{v unvisited} minOut(v)`,
where `minOut(x)` is the cheapest edge leaving x. Every unvisited city and u must still be left once, each by an edge at least
as costly as its cheapest, so this never exceeds the true best completion — the optimum is never pruned.

## 3. NP-Hard / NP-Complete (be precise)

* **TSP.** Optimisation (min-cost tour) is **NP-Hard**. Decision ("is there a tour of cost ≤ K?") is **NP-Complete**.
  Exact methods are therefore limited to small n (framework: backtracking ≤ 8, B&B ≤ 13, refusal above).
* **Hamiltonian cycle/path.** Decision problem is **NP-Complete**.
* **0/1 Knapsack.** DP is **pseudo-polynomial** O(nW): polynomial in the *value* W, exponential in its bit-length.
  Decision version is NP-Complete. **Fractional Knapsack** is polynomial (greedy).
* **N-Queen.** Standard N-Queen is **not** labelled NP-Complete; backtracking is exponential in the worst case, yet solutions
  can be constructed directly for n ≥ 4.
* MST, all-pairs shortest paths, Matrix Chain, tree and heap operations: polynomial.

## 4. Experiments and what they show

Generated by `python experiments/benchmark.py` and live on the `/experiments` page. Operation counts are deterministic.

1. **MST sparse → dense.** Prim-matrix does exactly 2V² operations whatever E is; Kruskal's work grows with E·log E.
   The rule switches where the two curves cross (for V = 200, around 30 % density). Prim-heap is O(E log V) like Kruskal
   and measured at roughly twice Kruskal's operations in this lazy-heap implementation.
   *Wall-clock caveat:* in CPython Kruskal is usually fastest in milliseconds because `sorted()` is native C.
2. **Floyd–Warshall.** ops/V³ = 1.0 exactly; doubling V multiplies measured time by about 7–8× (theory: 8×).
3. **TSP.** Backtracking states grow ≈ (n−1)!: 109,601 states at n = 9, 986,410 at n = 10 (a 9× jump).
   Branch & bound (same optimal cost) needs 7,828 and 15,018 — pruning helps by 1–2 orders of magnitude but does not change the worst case.
4. **Trees.** For 5,000 keys: Red-Black height ≈ 15, B-Tree (t = 16) height 3, and about 4× fewer node visits per search —
   so B-Tree wins when each node visit is a disk read. In RAM the B-Tree does more in-node comparisons, so Red-Black is not slower.
5. **Heaps.** Fibonacci insert is O(1) (1 step vs ≈ log n); decrease-key steps grow with the escalation ratio; Binomial keeps
   worst-case bounds. Step counts ignore constant factors, so the page also reports wall-clock.
6. **Knapsack.** DP cells = n·W grow with the number W; fractional greedy stays negligible; fractional value ≥ 0/1 value always; ratio-greedy on whole
   projects can be strictly worse (160 vs 220 in the demo).

## 5. Gaps in classic algorithms that led to newer ones (rubric item)

| Classic technique | Gap | Newer development |
|---|---|---|
| Binomial Heap | decrease-key and insert O(log n) | Fibonacci Heap, O(1) amortized; Prim/Dijkstra in O(E + V log V) |
| Plain BST | height O(n) on sorted input | Red-Black / AVL trees (height O(log n)) |
| Red-Black Tree on disk | ≈ log₂n page reads | B-Tree (log_t n page reads) |
| Prim vs Kruskal | neither dominates across densities | Borůvka, Fredman–Tarjan |
| Floyd–Warshall | O(V³) wasteful on sparse graphs | Johnson's algorithm O(V² log V + VE) |
| Greedy for 0/1 Knapsack | not optimal | DP O(nW); FPTAS when W is huge |
| Exact TSP backtracking | (n−1)! | Branch & bound; Held–Karp O(n²2ⁿ); Christofides 1.5-approximation for metric TSP |
| Brute-force N-Queen | n! placements | backtracking with early pruning |

## 6. Limitations (say these in the viva)

* Data-structure and TSP "step" counts are algorithmic steps, not hardware-level costs; wall-clock is machine- and Python-dependent.
* B-Tree page accesses are modelled by node visits; no real disk I/O is performed.
* Thresholds (heap rule, TSP limits) are design choices documented as constants.
* 0/1 Knapsack requires integer inputs and W ≤ 20000; B&B uses a simple lower bound (stronger bounds such as the 1-tree or reduced-matrix bound would prune more).
* No approximation or heuristic TSP is included because it is outside the prescribed syllabus.
